# 项目索引生成

当用户要求为一个已有项目生成、补全或更新 `PROJECT_INDEX.md`，或希望得到类似 `broker-core` 的项目总入口时，使用本 Skill。

## 目标产物

在目标项目根目录生成或更新：

- `PROJECT_INDEX.md`：项目总入口，只保留项目范围、阅读规则、分类入口和事实摘要。
- `docs/index/` 下的主题索引：仅为项目中确实存在且有足够证据的主题创建文件。可选主题包括源码、功能、环境、管理页面、外部依赖、数据链路、运维和术语。

根索引的组织方式参考 `broker-core/PROJECT_INDEX.md`：先说明如何阅读，再用表格链接到下级索引，最后记录事实边界、核实日期和依据。较大的项目应拆分下级索引，避免把完整源码说明塞进根文件；较小的项目可以只使用根文件。

## 工作流程

### 1. 确定范围与现状

1. 确认项目根目录，优先使用 Git 根目录；用户明确指定的目录优先。
2. 检查是否已有 `PROJECT_INDEX.md`、`docs/index/`、`README`、项目级 `AGENTS.md` 或其他索引文档。
3. 已有索引时先理解其结构和维护约定，再做增量更新；保留仍然有证据支持的人工补充内容。

### 2. 以证据为依据建立地图

使用 `rg --files`、`git ls-files` 和有边界的目录查看，按任务需要阅读文件，不要默认递归打开整个项目。优先检查：

- 构建清单和依赖文件（如 `go.mod`、`package.json`、`pom.xml`、`Cargo.toml`、`pyproject.toml`）；
- 启动入口、命令、服务装配、路由、Handler/Controller、任务调度和核心模块；
- 配置模板、环境变量、部署文件、CI 配置和运行手册；
- 现有功能文档、数据库迁移、消息主题、外部服务客户端和管理页面路由。

把“目录存在”与“功能已实现”区分开。每个重要结论都要能回链到源码、配置或文档；无法核实时写“待核实”，禁止猜测。

### 3. 设计最小且可导航的索引

根 `PROJECT_INDEX.md` 至少包含以下部分：

1. 项目标题和用途说明；
2. **阅读规则**：先按任务选择分类，按需展开，禁止无目的递归阅读；
3. **索引维护要求**：源码路径、调用链、接口、配置、依赖、消息主题、页面或运维流程变化时同步更新；
4. **分类入口**：用表格列出实际存在的下级索引、内容和阅读时机；
5. **事实与范围**：技术栈、重要架构事实、收录范围和明确的未知项；
6. **最近核实**：使用当前日期，并列出核实依据。

按证据选择下级索引，不要为了套模板创建空文件：

| 主题 | 应覆盖的内容 |
|---|---|
| 源码 | 顶级目录、启动入口、服务/组件、内部模块 |
| 功能 | 业务功能入口、关键调用链、对应源码和详细文档 |
| 环境 | 配置来源、环境差异、部署地址和生效方式 |
| 管理页面 | 页面用途、路由、源码入口和环境地址引用 |
| 依赖 | 外部服务、中间件、关联仓库和定位依据 |
| 数据链路 | 请求、事件、队列、状态、投影、存储和一致性边界 |
| 运维 | 构建、测试、发布、排障、恢复和操作前置条件 |
| 术语 | 领域词汇、ID、状态、水位和容易混淆的概念 |

下级索引应包含返回根入口的相对链接、定位表格、必要的边界说明、最近核实日期和证据来源。URL、配置值和部署信息按环境或来源集中维护，其他页面通过链接引用，避免复制产生漂移。

### 4. 校验并交付

写入前检查：

- 所有本地 Markdown 链接都相对于所在文件计算，并指向存在的文件或标题；
- 文件名、目录名、命令、服务名和配置键与当前仓库一致；
- 没有把密码、Token、私钥、带密码 DSN 或 webhook secret 写进索引；
- 明确区分当前实现、设计方案、历史记录和废弃内容；
- 索引只描述已核实事实，未核实内容标记“待核实”；
- 变更范围只包含项目索引及其必要的下级索引，不修改业务源码或无关文档。

最后报告生成或更新的文件树、主要入口、核实依据和仍待核实的项目。若发现现有索引与源码矛盾，优先指出冲突并以当前源码/配置为依据更新，不能静默保留错误事实。

## 维护规则

索引是定位入口，不是源码副本。功能细节、完整接口字段和操作步骤应链接到已有文档或源码。修改索引时同步更新上级链接和核实日期；新增、删除或移动下级索引时同步调整根入口。管理 URL 的实际值只在对应环境文件维护，密钥只记录获取方式或引用位置。

需要决定章节或表格形状时，使用以下最小骨架，并删除没有证据支持的主题：

```markdown
# {项目名称} 项目索引

本文件是项目总入口，用于定位源码职责、功能实现、环境配置、外部依赖和运维资料。

## 阅读规则

先根据当前任务定位相关分类，再按需阅读对应下级索引、详细文档和源码。禁止默认递归读取全部下级文件。

## 索引维护要求

- 源码路径、调用链、接口、配置、依赖、消息主题、页面或运维流程变化时同步更新。
- 未核实的信息标记“待核实”，不得猜测；密钥只记录引用或获取方式。
- 修改索引时同步更新最近核实日期和依据，并验证本地链接。

## 分类入口

| 索引 | 包含内容 | 何时阅读 |
|---|---|---|
| [源码目录](docs/index/source.md) | 顶级目录、启动入口、内部模块 | 定位代码或了解职责 |

## 事实与范围

- {基于源码或配置核实的项目事实}
- {明确收录或不收录的范围}
- {仍待核实的事项}

最近核实：{YYYY-MM-DD}。依据：{源码、配置、文档或用户提供的信息}。
```
